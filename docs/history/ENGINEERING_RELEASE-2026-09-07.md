## Worklet timing and continuous live playback

- Measure real `AudioWorkletProcessor.process()` execution, not source-clock arithmetic as a substitute.
- Compare callback duration with the measured context's 128-frame budget. At 96 kHz that budget is approximately 1.333 ms.
- Retain wall-time brackets around CDP calls so scheduling or IPC delay is visible separately from source/context drift.
- Trace loss or missing callback records invalidate profiling acceptance.
- Prove at least ten minutes of real SoundCloud playback with continuous output evidence. Existing twenty-second analyser samples do not satisfy this requirement.
- Preserve earlier failed runs. Do not loosen assertions to conceal failures.

## Standard build pipeline

- Replace both the userscript string-insertion build and bespoke audio bundler with esbuild and explicit module dependencies.
- Emit IIFE output with an automatically generated userscript metadata banner, deterministic artifacts and readable source maps.
- Bundle the pinned WASM payload and worklet code as local assets. Remove obsolete CDN dependency assumptions from installation, tests and documentation.
- `esbuild-plugin-inline-worker` creates Web Workers, not AudioWorklets. Preserve the AudioWorklet execution context through a compatible esbuild asset-loading path.
- Do not disguise concatenation as a migration by passing the old assembled monolith to esbuild.

The website engine also builds directly through esbuild, with no vendor/adapter concatenation. Buffered playback uses a separately compiled worklet asset and locally bundled Mediabunny module exports. Runtime worklet assembly is removed; standalone renderer, transport and owner fixtures consume the compiled asset. Content-addressed worklet JavaScript and its separate original-source map are persisted with candidate builds. The public download is unchanged.

This confirms low-rate variation exists without missed audio deadlines, consistent with upstream random phase prediction. It does not establish the sole cause of prior pitch failures or clear them. No production code, vendor bytes or acceptance tolerances changed.
